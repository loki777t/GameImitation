# 1.Формулировка задачи

## 1.1. На какую аудиторию рассчитываем
Мы рассчитываем на молодую аудиторию в возрасте от 10 до 25 лет.

Портрет ЦА: Школьники и студенты, увлекающиеся видеоиграми (CS2, Dota 2, Valorant, Fortnite, Minecraft). Чаще всего это пользователи бюджетных или устаревших ПК/ноутбуков, которые сталкиваются с низким FPS, фризами и микро-лагами. Они активны в интернете, следят за стримерами и доверяют мнению кумиров.

Боли: «Лагает комп», «видеокарта тянет, но фризы есть», «хочется играть как у стримера — плавно».

## 1.2. На какой трафик рассчитываем
На начальном этапе рассчитываем на органический и таргетированный трафик через посредников (стримеров):

Источники: Реклама у начинающих стримеров на платформе Twitch (также рассматриваем VK Play Live и YouTube).

Объем: Сотрудничество с 10-15 микростримерами (1-15 зрителей) для теста гипотезы. Охват — от 500 до 2000 уникальных зрителей в день.

## 1.3. Что хотим продать
Мы продаем подписку на программу Game Imitation.

Продукт: Утилита для оптимизации Windows и буста FPS.

Цена: 500 рублей в месяц.

Триал: Бесплатный пробный период 3 дня для демонстрации эффективности.

## 1.4. Как мы этого будем добиваться

Разработка программы (софта) с функциями очистки RAM, отключения фоновых процессов, твиков реестра и сетевых настроек (для снижения инпут лага).

Создание простого и красивого сайта (лендинга) с описанием функций.

Запуск реферальной/партнерской программы для стримеров (скидка или % за каждого приведенного друга).

Спагетти-маркетинг: покупка рекламы у микро-инфлюенсеров на Twitch (аудитория там лояльнее всего относится к подобному софту).

# 2. Техническое задание (ТЗ)
Цель: Разработать MVP (минимально жизнеспособный продукт) — десктопное приложение для ОС Windows.

Состав:

Клиентская часть (GUI): Простое окно с кнопкой «Оптимизировать» и индикаторами состояния системы (FPS монитор, загрузка ЦП/ОЗУ). Стиль — геймерский (темная тема, неон).

Ядро (Скрипты и автоматизация):

Очистка кэша DNS.

Отключение визуальных эффектов Windows.

Завершение «тяжелых» фоновых процессов.

Настройка параметров электропитания (Макс. производительность).

Отключение Xbox Game Bar и ненужных служб.

Бэкенд:

Система авторизации (логин/пароль).

Система оплаты (ЮKassa / Robokassa).

Система выдачи триал-ключей (на 3 дня).

Сайт: Одностраничный лендинг (промо + кнопка скачать).

# 3. Проектирование
## 3.1 UserFlow (Путь пользователя)
Привлечение: Юзер смотрит стрим -> Стример говорит: «Игра стала плавной после Game Imitation, ссылка в описании».

Переход: Юзер кликает на ссылку -> попадает на лендинг.

Ознакомление: Читает преимущества (Буст FPS, убирает лаги), видит цену (500р) и кнопку «Попробовать бесплатно 3 дня».

Регистрация: Вводит email, получает пробный ключ/ссылку на скачивание.

Установка: Скачивает .exe, устанавливает, запускает, нажимает «БУСТ!».

Результат: Видит прирост FPS или плавность, заходит в игру, убеждается.

Оплата: Через 3 дня (или сразу) получает предложение купить подписку за 500р. Оплачивает картой.

## 3.2 Дизайн-проект
Стиль: Нео-геймерский, минимализм, агрессивный гейминг.

Цвета: Темно-серый (#121212), черный, ярко-зеленый неон (#39FF14) или синий (#00FFFF) для акцентов.

Шрифты: Гротески (Montserrat, Bebas Neue) для заголовков.

Логотип: Стилизованная аббревиатура GI или контроллер, состоящий из линий.

Экран программы:

Большая кнопка «OPTIMIZE NOW».

Счетчики (CPU, RAM, FPS Target).

Лента последних оптимизаций (очищено памяти X MB).

# 5. Проект
На данном этапе подразумевается, что в репозитории лежит работающий код, который:

Собирается в установщик (Inno Setup).

При запуске проверяет наличие ключа в реестре/файле.

Если ключ валидный (или триал активен), применяет набор оптимизаций (чистит Temp, отключает службы, меняет параметры реестра для приоритета игр).

# 7. Оптимизация
## 7.1 Для чего нужна оптимизация
Оптимизация внутри самой программы нужна для того, чтобы она сама не жрала ресурсы (не создавала лаги), а также для ускорения работы скриптов.

## 7.2 Что будем оптимизировать
Алгоритмы поиска мусора: Чтобы не сканировать весь диск часами.

Интерфейс: Чтобы отрисовка UI не грузила процессор.

Время запуска: Чтобы программа открывалась быстро.

База данных твиков: Ускорить применение настроек реестра.

## 7.3 Как будем оптимизировать
Многопоточность: Вынос тяжелых задач (очистка) в фоновые потоки.

Кэширование: Сохранять список стандартных процессов, чтобы не пересчитывать каждый раз.

Компиляция: Вместо интерпретируемого Python использовать компилируемые языки (C++/Rust) для критических частей или компиляцию в EXE с оптимизациями.

## 7.4 Сравнительные результаты
До: Программа грузила ЦП на 15% во время сканирования. Время сканирования 60 сек.

После: Программа грузит ЦП на 2-5%. Время сканирования 10 сек.

# 9. Гитфлоу (GitFlow)
Ветки в репозитории:

main — только стабильный, релизный код.

develop — ветка разработки.

feature/\* — для новых фич (например, feature/new-antilag-module).

hotfix/\* — для срочных исправлений багов в проде.

release/\* — для подготовки нового релиза.

Правило: Нельзя пушить в main напрямую. Только через Pull Request (или Merge Request) с проверкой.
